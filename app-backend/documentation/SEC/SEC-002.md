# SEC-002 — Validar propiedad al marcar notificaciones

## Contexto
Los usuarios pueden marcar notificaciones individuales como leídas.

## Problema
La actualización usa el ID global y no comprueba `userId`.

## Evidencia
`notifications.controller.ts` y `notifications.service.ts`, símbolo `markAsRead`.

## Impacto
Un usuario autenticado puede alterar notificaciones ajenas.

## Propuesta
Actualizar por identificador y propietario autenticado, devolviendo 404 para recursos ajenos.

## Prioridad
Alta. Autorización horizontal.

## Dependencias
Ninguna.

## Criterios de aceptación
- Una notificación propia cambia a leída.
- Una notificación ajena permanece intacta y devuelve 404.
- Un ID inexistente devuelve 404 sin revelar propietarios.

## Pruebas recomendadas
- Positiva: marcar una notificación propia; resultado esperado: `isRead=true`.
- Negativa: usar el ID de otro usuario; resultado esperado: 404 y cero cambios.
- Caso límite: usar un ID inexistente; resultado esperado: 404 controlado.

## Estado
Propuesta aprobada para implementación.
